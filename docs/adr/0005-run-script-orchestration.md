# The agent may run ad-hoc orchestration scripts that call Tools but hold no Capabilities

A new built-in, `run_script`, lets the agent submit one QuickJS script per step that calls loaded registry Tools as async functions, so loops, filters, branches and parallel fan-out run in the sandbox instead of costing one model round trip each, and intermediate results never enter model context. The script holds **no Capabilities of its own**: it gets no `fetch`, `fs`, `process`, `env`, `clipboard`, `notify`, `llm`, `agents` or `store`, only the Tools named in its `uses` list plus `console`, `JSON`, timers and `requireModule`. Every effect still happens inside a persisted, versioned, approved and measured Tool, so ADR 0002's premise holds: capability grows only in the registry. A script that proves useful is promoted into a real Tool through the normal `create_tool` gate (`save_as`), and the optimiser flags scripts that recur across Sessions. To make fan-out real, nested `tools.call` becomes asynchronous: it returns a Promise settled by the daemon, and each nested Invocation runs on its own sandbox thread (§6.1), bounded by `scripts.max_parallel`. We rejected a general code sandbox with Capabilities, which would recreate the starter shell ADR 0002 rejected and let scripts replace Tools. We also rejected exposing Tools only as a code API with no direct function calls, as Cloudflare Code Mode does: `find_tools` declaring real functions keeps the cached prompt prefix stable and shows the provider exact schemas.

**Status:** proposed

**Considered Options:** no code mode (status quo; parallelism only through provider-emitted parallel tool calls); a script sandbox with its own declared Capabilities; code-API-only Tool exposure (Codex / Cloudflare Code Mode); a script built-in with no Capabilities (chosen).

**Consequences:** The runtime's synchronous `__call` bridge must support Promise-returning host calls, at least for `tools_call`. Composed registry Tools benefit from this too, so it ships first as its own change. Approval moves from per tool call to the declared `uses` set in the existing pre-pass, and a call outside that set fails rather than prompting partway through a script. Scripts are recorded as Invocations of `run_script` for audit and the live tree, but they are never optimised and never replayed, so the bootstrap prompt must steer the agent toward saving any script it would run twice.
