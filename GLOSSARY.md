# Formless

A general-purpose agent harness that boots with a single tool-building tool and grows its own capabilities for any use case, rather than specialising in coding. It is centred on a daemon core that user interfaces connect to.

## Language

**Formless**:
A general-purpose agent harness that starts from a single bootstrap tool and builds the tools it needs for the task at hand.
_Avoid_: Coding agent, form library, chatbot

**Bootstrap Tool**:
The one tool available at first boot, used to create every other tool. In Formless this is `create_tool`.
_Avoid_: Meta-tool, seed tool

**Tool**:
A persisted, versioned capability created through the Bootstrap Tool, with a name, description, input schema, and sandboxed script implementation.
_Avoid_: Plugin, extension, function

**Daemon Core**:
The long-lived local process that owns the agent loop, tools, sessions, and state, and that interfaces connect to.
_Avoid_: Server, backend, engine

**Tool Success Rate**:
The measured share of a tool's invocations that succeed, used as the primary signal for self-optimisation.
_Avoid_: Accuracy, score

**Self-Optimisation**:
The harness improving its own tools over time, driven by measured Tool Success Rate.
_Avoid_: Self-improvement, auto-tuning

**Session**:
One user's continuous conversation and task history with the harness, resumable after interruption. Many Sessions run concurrently against one Daemon Core.
_Avoid_: Thread, chat, connection

**Run**:
One unit of work inside a Session, started by a user message and continuing until the agent answers or the user interrupts it. A Run has no step, token, or time limit.
_Avoid_: Task, job, turn

**Invocation**:
A single execution of one version of a Tool with one input. Invocations are recorded and measured for Tool Success Rate.
_Avoid_: Call, execution, request

**Steer**:
A user message sent while a Run is active that is injected into the Run at the next step boundary. In Formless, pressing Enter during a Run steers by default; queueing a message for after the Run is the alternate action.
_Avoid_: Interrupt, interjection

**Pending Invocation**:
An Invocation that has exceeded the soft time threshold (default 300s) without finishing. It keeps running in the background while the agent receives a handle to poll, await, or abandon it.
_Avoid_: Timed-out invocation, hung tool, background job

**Capability**:
A declared permission a Tool needs, such as network access or filesystem access to a path. A Tool can never exceed its declared Capabilities.
_Avoid_: Permission, scope

**Candidate**:
A proposed new version of a Tool, generated by Self-Optimisation and not yet promoted. A Candidate must beat the current version in sandboxed replay before promotion.
_Avoid_: Draft, patch

**Promotion**:
Replacing the current version of a Tool with a Candidate that measurably outperformed it in sandboxed replay. Every version is kept for rollback.
_Avoid_: Deploy, release

**Retired Tool**:
A Tool the agent has removed from the callable registry. Its versions and Invocation history are retained and it can be restored; only the user can permanently purge it.
_Avoid_: Deleted tool, disabled tool

**Compaction**:
Replacing older Session history and tool output with a persisted summary checkpoint so a Run can continue within the model's context window. Large tool outputs are kept in full as artifacts on disk.
_Avoid_: Truncation, summarisation

**Relay**:
A future hosted intermediary that a Daemon Core connects out to with encryption, so a hosted frontend can reach a local daemon. Not in v1.
_Avoid_: Proxy, tunnel
